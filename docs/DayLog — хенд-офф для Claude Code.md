# DayLog — хенд-офф для Claude Code

Oct 12, 2026 · @Kirill

## Контекст и цель

DayLog — личное приложение для одного пользователя, которое показывает, куда реально уходит день, и сравнивает это с тем, что было запланировано. Цель — увидеть масштаб прокрастинации в цифрах (часы на игры и соцсети за неделю) и вернуть контроль через простой план дня с привычками.

Приложение решает две задачи:

- **Пост-аналитика дня.** Пользователь задним числом заносит, что делал в какие интервалы времени, и видит долю дня и недели на сон, еду, дорогу, работу, развлечения и т.д. Плюс фиксирует мелкие выполненные дела (погладил одежду, заправил кровать), которые не планировал.
- **План на день и неделю.** Разовые задачи и регулярные привычки с наглядным статусом: сделал, пропустил или забил.

Публичность не нужна: один пользователь, доступ только у владельца. Главный критерий успеха — запись занятия занимает меньше 10 секунд, иначе инструментом не будут пользоваться.

## Ключевые сценарии

Пять сценариев покрывают весь MVP; каждый должен работать с телефона одной рукой.

1. **Быстрая запись «что я делал».** Открываю приложение, вижу «С 14:20 не учтено». Жму на пресет «Dota 2» — блок 14:20–сейчас записан. При необходимости двигаю начало и конец.
2. **Вечерний разбор дня.** Смотрю таймлайн за день, закрываю пустые промежутки, отмечаю привычки и задачи. Вижу итог: 4 ч развлечений, 1,5 ч дороги, 3 из 5 задач сделано.
3. **Мелкое дело без плана.** Вписываю «погладил рубашки» в поле «Сделал» — оно падает в список выполненного за сегодня одним действием.
4. **План на день и неделю.** В воскресенье раскидываю задачи по дням недели, часть оставляю «на неделе без даты». Утром вижу список на сегодня вместе с привычками.
5. **Недельный обзор.** Открываю аналитику: структура недели по категориям, сравнение с прошлой неделей, процент выполнения плана и привычек, часы развлечений по дням.

## Скоуп MVP и не-цели

MVP — это учёт времени, задачи, привычки и аналитика; всё «умное» откладывается до момента, когда привычка вносить данные закрепится.

**Входит в MVP**

- Учёт времени: интервалы с категорией и активностью, таймлайн дня, пресеты, подсветка неучтённого времени.
- Справочник категорий и активностей с цветами, редактируемый.
- Разовые задачи на конкретный день или «на неделе», статусы: открыта, сделана, пропущена.
- Быстрая запись мелких выполненных дел без плана.
- Привычки с расписанием и отметками по дням.
- Аналитика за день, неделю, месяц.
- Вход только для владельца, PWA для телефона, экспорт данных в CSV и JSON.

**Не входит (не делать без явного запроса)**

- Многопользовательность, шеринг, соцфункции.
- Автотрекинг экранного времени и интеграции с Instagram, Steam и т.п.
- Live-таймер «старт/стоп» — только как опция в фазе 4.
- Геймификация, очки, уровни.
- AI-рекомендации и анализ текстом.
- Нативные приложения iOS/Android.

## Модель данных

Шесть основных таблиц плюс `settings`; все времена хранятся как `timestamptz` в UTC, отображаются в часовом поясе пользователя (по умолчанию Europe/Moscow). У каждой таблицы есть `id uuid`, `user_id uuid` (RLS: `user_id = auth.uid()`), `created_at`, `updated_at`.

| Таблица | Ключевые поля | Назначение |
| --- | --- | --- |
| `categories` | `name`, `color`, `kind` (`productive` · `maintenance` · `rest` · `leisure`), `sort_order`, `archived` | Верхний уровень: Сон, Еда, Дорога, Работа, Саморазвитие, Быт, Спорт, Общение, Развлечения, Прочее |
| `activities` | `category_id`, `name`, `is_preset`, `sort_order`, `archived` | Конкретные занятия: Dota 2, Instagram, YouTube, Метро. Пресеты показываются чипами быстрого ввода |
| `time_entries` | `started_at`, `ended_at`, `activity_id` или `category_id`, `note`, `intentional` (bool, nullable) | Интервал времени. `intentional = false` помечает «залип, не планировал» |
| `tasks` | `title`, `scheduled_date` (date, nullable), `week_start` (date, nullable), `status` (`open` · `done` · `skipped`), `done_at`, `is_unplanned` (bool), `note`, `sort_order` | Разовые задачи и мелкие дела. Мелкое дело = задача с `is_unplanned = true`, созданная сразу в статусе `done` |
| `habits` | `title`, `schedule_type` (`daily` · `days_of_week` · `times_per_week`), `days_of_week` (int\[\]), `times_per_week` (int), `active_from`, `archived_at` | Регулярные привычки |
| `habit_checks` | `habit_id`, `date`, `status` (`done` · `skipped`) | Отметка по дню. Уникальность `(habit_id, date)`; отсутствие записи = не отмечено |

**Правила целостности**

- Интервалы `time_entries` не пересекаются. При сохранении пересекающегося интервала UI предлагает обрезать соседний.
- `ended_at > started_at`, длительность не больше 24 ч.
- У задачи задан либо `scheduled_date`, либо `week_start` (понедельник), либо ничего (бэклог).
- **Граница дня** — настройка `day_start_hour` (по умолчанию 04:00), чтобы ночь до 4 утра относилась к предыдущему дню. Хранится в таблице `settings` (одна строка на пользователя) вместе с часовым поясом.
- Сон, пересекающий границу дня, в аналитике режется по границе, а не приписывается целиком одному дню.

Сидинг: при первом входе создаются 10 категорий выше и около 15 пресетов активностей; всё редактируется.

## Экраны и UX

Четыре экрана, нижняя навигация на телефоне и боковая на десктопе. Mobile-first: основная работа идёт с телефона.

| Экран | Что на нём | Ключевые действия |
| --- | --- | --- |
| **Сегодня** | Вертикальный таймлайн дня (от границы дня до текущего момента), цветные блоки по категориям, серые полосы «не учтено». Ниже — чеклист задач на сегодня и привычек, список «Сделал сегодня» | Плашка «С 14:20 не учтено» + чипы пресетов: один тап записывает блок от конца последней записи до «сейчас». Тап по блоку — редактирование. Поле «Сделал…» с Enter создаёт мелкое дело |
| **План** | Неделя из 7 колонок (на телефоне — список по дням), блок «На неделе без даты», бэклог. Сетка привычек: строки — привычки, колонки — дни | Добавить задачу в день, перенести (drag на десктопе, меню «Перенести» на телефоне), отметить привычку |
| **Аналитика** | Переключатель День / Неделя / Месяц и стрелки навигации по периодам. Графики описаны в разделе «Аналитика» | Сравнение с предыдущим периодом |
| **Настройки** | Категории и активности (цвет, порядок, архив), привычки, граница дня, часовой пояс, экспорт CSV/JSON | — |

**Принципы ввода времени**

- По умолчанию новый блок начинается там, где закончился предыдущий. Пользователь почти никогда не вводит начало вручную.
- Время выбирается шагом 5 минут; есть быстрые кнопки «−15 мин» / «+15 мин».
- На вечернем разборе можно «закрасить» пустой промежуток: тап по серой полосе → выбор активности.
- Переключатель «Залип / Осознанно» показывается только для категорий типа `leisure`, по умолчанию не выбран.
- Неотмеченные к концу дня задачи не удаляются: на следующий день они видны в блоке «Хвосты» с кнопками «Перенести на сегодня» и «Пропустить».

Визуальный стиль — спокойный, без геймификации; каждая категория имеет свой цвет, один и тот же во всех экранах.

## Аналитика

Аналитика отвечает на три вопроса: куда ушло время, сколько из него «слито», и выполнен ли план. Все расчёты — чистые функции в `lib/analytics` с юнит-тестами; периоды режутся по границе дня.

| Метрика | Формула | Визуализация |
| --- | --- | --- |
| Структура времени | Длительность по категории, обрезанная по границам периода; доля от учтённого и от полного периода (24 ч × дни) | День — горизонтальная полоса 24 ч; неделя/месяц — donut + таблица часов |
| Структура по дням | Часы по категориям на каждый день периода | Stacked bar, один столбец на день |
| Неучтённое время | Длина периода до текущего момента − учтённое | Серый сегмент во всех графиках, отдельной цифрой |
| Развлечения | Сумма по категориям `leisure`; отдельно — доля с `intentional = false` | Крупная цифра + дельта к прошлому периоду, топ-5 активностей |
| Выполнение задач | `done / (done + skipped + open)` по задачам, запланированным на период; мелкие дела (`is_unplanned`) не входят в знаменатель | Процент + список «не сделано» |
| Мелкие дела | Количество `is_unplanned` за период | Счётчик и список |
| Привычки | По каждой: отмеченные `done` / запланированные вхождения по расписанию; `times_per_week` считается по неделе | Сетка-тепловая карта, текущая серия (streak) |
| Сон | Средняя длительность и среднее время отхода ко сну | Цифра + линия по дням |

Каждая цифра в аналитике сопровождается дельтой к предыдущему такому же периоду (эта неделя vs прошлая). Будущее время в текущем периоде не считается неучтённым.

## Стек и архитектура

Стек повторяет уже знакомый по QuestLog: Next.js + TypeScript + Supabase, деплой на Vercel, установка на телефон как PWA. Это даёт синхронизацию телефон ↔ ноутбук без своего бэкенда и бесплатно на одного пользователя.

| Слой | Выбор | Комментарий |
| --- | --- | --- |
| Фреймворк | Next.js (App Router), TypeScript strict | Server Components для чтения, Server Actions для записи |
| UI | Tailwind CSS + shadcn/ui | Тёмная и светлая тема |
| Графики | Recharts | Donut, stacked bar, линии |
| Даты | date-fns + date-fns-tz | Вся логика границы дня и часового пояса — в одном модуле `lib/time` |
| БД и auth | Supabase Postgres + Supabase Auth (magic link) | RLS на всех таблицах; регистрация отключена, вход разрешён только для email владельца |
| Валидация | Zod | Общие схемы для форм и Server Actions |
| Состояние клиента | TanStack Query | Оптимистичные обновления — запись блока должна отображаться мгновенно |
| PWA | Web App Manifest + service worker (Serwist) | Иконка на домашнем экране, кэш оболочки приложения |
| Тесты | Vitest для `lib/`, Playwright для 2–3 ключевых сценариев | Обязательно покрыть нарезку интервалов по границам дня |
| Хостинг | Vercel (Hobby) | Приватность обеспечивает auth; домен не нужен |

**Структура репозитория**

```
app/(app)/today · plan · analytics · settings
app/login
lib/time        — граница дня, часовой пояс, нарезка интервалов
lib/analytics   — чистые функции расчёта метрик
lib/db          — запросы к Supabase, типы из supabase gen types
supabase/migrations
docs/SPEC.md    — этот документ
CLAUDE.md       — правила для Claude Code
```

Альтернатива без облака — локальное хранение в IndexedDB (Dexie) с экспортом в файл. Проще и полностью приватно, но без синхронизации между телефоном и ноутбуком; см. «Открытые решения».

## Поэтапный план

Пять фаз; после фазы 1 приложением уже можно пользоваться для учёта времени, поэтому её надо закончить как можно раньше. Каждая фаза завершается рабочим деплоем на Vercel.

1. **Фаза 0 — каркас.** Next.js + Tailwind + shadcn/ui, подключение Supabase, magic-link вход с allowlist по email, миграции всех таблиц с RLS, сидинг категорий и пресетов, PWA-манифест, деплой.
2. **Фаза 1 — учёт времени.** Модуль `lib/time` с тестами, CRUD `time_entries`, экран «Сегодня» с таймлайном, плашка «не учтено с …» и чипы пресетов, редактирование блока, проверка пересечений, заливка пустых промежутков.
3. **Фаза 2 — задачи и привычки.** CRUD задач и привычек, чеклист на «Сегодня», поле «Сделал…» для мелких дел, экран «План» с неделей и бэклогом, сетка привычек, блок «Хвосты».
4. **Фаза 3 — аналитика.** `lib/analytics` с тестами, экран «Аналитика»: все метрики из раздела выше, переключение периодов, дельты к прошлому периоду.
5. **Фаза 4 — полировка.** Экспорт CSV/JSON, офлайн-кэш оболочки, настройки категорий и привычек, тёмная тема. Опционально: live-таймер старт/стоп и вечернее push-напоминание «разбери день».

Правило работы: Claude Code начинает каждую фазу с короткого плана в чате, ждёт подтверждения, затем реализует и в конце прогоняет тесты и линтер.

## Критерии приёмки

MVP готов, когда выполнены все пункты ниже на реальном телефоне.

- [ ] Чужой email не может войти; без входа ни один экран и ни одна строка БД недоступны.
- [ ] Запись блока «от последней записи до сейчас» через пресет — не больше 2 тапов и 10 секунд.
- [ ] Пересекающиеся интервалы не сохраняются молча: пользователь видит конфликт и выбирает, как его разрешить.
- [ ] Сон 23:30–07:30 корректно делится между двумя днями при границе дня 04:00 и без неё.
- [ ] Неучтённое время отображается на таймлайне и в аналитике, будущее время не считается неучтённым.
- [ ] Мелкое дело добавляется одним вводом с Enter и сразу видно в «Сделал сегодня».
- [ ] Привычка «3 раза в неделю» считается выполненной за неделю при любых трёх отметках.
- [ ] Невыполненные задачи вчерашнего дня видны в «Хвостах».
- [ ] Аналитика недели показывает доли по категориям, часы развлечений, % плана и привычек с дельтой к прошлой неделе.
- [ ] Приложение устанавливается на домашний экран и открывается без адресной строки.
- [ ] Экспорт отдаёт все данные пользователя в CSV и JSON.
- [ ] `lib/time` и `lib/analytics` покрыты тестами, CI (или локальный `pnpm test`) зелёный.
